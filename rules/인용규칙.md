# 인용규칙 — 조문·판례 표기와 출처 핀

모든 서면·리서치 산출물의 법령·판례 인용은 이 규칙을 따른다.
**이 규칙의 존재 이유: 모든 인용을 기계 검증 가능하게 만드는 것.**

## 1. 법령 인용

- 본문 표기: `근로기준법 제27조`, `민법 제750조 제1항` (정식 법령명 + 조·항·호)
- 모든 법령 인용 직후에 출처 핀 병기:

  `[출처: kr/근로기준법/법률.md | 현행확인 2026-06-12]`

  - 경로는 legalize-kr 저장소 루트 기준 실제 파일 경로.
  - 현행확인 날짜는 `git -C legalize-kr log -1 --format=%ad --date=short -- "kr/{법령}/{파일}.md"` 실행일.
- 시행령·시행규칙은 해당 파일(`시행령.md`, `시행규칙.md`)을 핀에 명시.
- 약칭(예: 주임법, 자배법)은 **검색용으로만** 사용한다(`rules/법령약칭.md` 참조).
  서면 본문과 출처 핀에는 항상 정식 법령명을 쓴다.

## 2. 판례 인용

- 본문 표기: `대법원 2010. 3. 25. 선고 2009다12345 판결` (법원명, 선고일, 사건번호, 판결/결정)
- 모든 판례 인용 직후에 출처 핀 병기:

  `[출처: 민사/대법원/대법원_2010-03-25_2009다12345.md]`

  - 경로는 precedent-kr 저장소 루트 기준 실제 파일 경로 (파일명 = 법원명_선고일_사건번호).
- **생사확인 라인.** 리서치 파일(`리서치/쟁점별_법리.md`)에서는 판례 출처 핀 바로 아래에
  후속 판례 역검색(사건번호로 precedent-kr 전체 Grep) 결과를 한 줄 기재한다:

  `[생사확인: YYYY-MM-DD 기준 precedent-kr 수록 범위 내 변경·폐기 판례 미발견]`

  변경·폐기 정황 발견 시:

  `[⚠️ 생사확인: 대법원 YYYY. M. D. 선고 ○○○○ 전원합의체 판결이 변경 선언 — 변호사 확인 필요]`

  - 역검색은 precedent-kr 수록 범위 내 휴리스틱이며, 판례 폐기 여부의 최종 판단은
    변호사가 한다. 미발견이 "현재 유효"를 보증하지 않는다.
  - 생사확인 라인은 리서치 파일 전용 표기로, 서면 본문에는 넣지 않는다.

## 3. 절대 규칙

1. **원문 발췌 없는 인용 금지.** 리서치 파일(`리서치/쟁점별_법리.md`)에 원문 발췌가
   없는 조문·판례는 어느 서면에도 인용할 수 없다.
2. **출처 핀 없는 법률 주장 금지.** 조문·판례를 언급하는 모든 문장에는 핀이 있어야
   하며, /verify-citations가 핀 없는 법률 주장을 ❌ 처리한다.
3. 출처 핀은 **초안 DOCX까지 유지**한다(검증 추적성). 최종 제출본에서 변호사가 제거한다.
   - 초안 DOCX에서 `[출처: …]`는 **빨간색**, `[변호사 확인 필요…]`는 **파란색**으로
     자동 표시된다(render_서면.py 후처리) — 변호사 검수 시 제거·확정 지점 식별용.
4. 수치·이율·기간 등 법정 값은 조문 원문에서 확인된 것만 쓴다. 미확인이면
   `[변호사 확인 필요]`를 본문에 표기하고 사건컨텍스트 `확인필요`에 적재한다.

## 4. 저장소 한계 고지

리서치 산출물 말미에 다음 문구를 고정 기재한다:

> 본 리서치는 legalize-kr·precedent-kr 저장소 수록 범위 내 검색 결과임.
> 저장소 외 최신 판례·하급심 판례는 별도 확인 필요.

## 5. 생사확인 표준 절차 (단일 출처 — 스킬은 이 절을 참조한다)

인용하려는 판례가 이후 변경·폐기되지 않았는지 확인하는 절차:

1. `git -C precedent-kr -c core.quotepath=false grep -l "{사건번호}"` 로
   저장소 전체 역검색 (대상 판례 자신의 파일은 제외).
2. 히트 중 파일명 선고일이 대상 판례 선고일 **이후**인 것만 후보로 남긴다.
3. 후보를 Read로 열어 사건번호 주변 맥락을 확인한다 — `변경`, `폐기`,
   `저촉되는 범위에서`, `전원합의체` 선언 동반 여부. 단순 "등 참조" 원용은
   변경이 아니다.
4. 결과를 §2의 생사확인 라인 형식으로 기재한다.

수행 주체별 차이:
- /legal-research: 변경·폐기 선언 발견 시 그 판례를 버리고 변경한 후속
  판례(현재 법리)로 교체. 불명확하면 발췌 유지 + ⚠️ 병기.
- /verify-citations: 리서치의 생사확인 라인을 **신뢰하지 말고 재수행**
  (검증자 독립성). 판정 기준은 verify-citations 스킬에 따른다.

## 6. 저장소 검색 규칙

- **precedent-kr에서 사건종류 단위 이상(전체·민사 등)을 검색할 때는 반드시
  `git -C precedent-kr -c core.quotepath=false grep -l "{패턴}"` 을 사용한다.**
  내장 Grep 도구는 대형 트리에서 매칭을 조용히 누락할 수 있음이 확인됨
  (2026-06-12 검증: 12만 파일 트리 검색에서 실재 매칭 파일 누락 재현).
- 내장 Grep은 단일 법원등급 디렉토리 범위(예: `precedent-kr/민사/대법원`)
  에서만 사용한다.
- legalize-kr(약 5,700파일)은 내장 Grep 사용 가능.

## 7. 행위시법 조회 표준 절차 (단일 출처 — 스킬은 이 절을 참조한다)

인용해야 하는 것은 "지금 파일에 있는 조문"이 아니라 **기준일에 시행 중이던
조문**이다. legalize-kr 커밋일은 공포·반영일이며 **시행일과 다르다** —
최신 커밋이 미래 시행 개정본일 수 있다(2026-06-12 확인: 근로기준법 HEAD는
시행 2027-06-10 개정본이고, 당시 시행 중 버전은 4커밋 전이었음). 따라서 버전
판정은 반드시 각 버전 frontmatter의 `시행일자`로 한다.

**기준일**: 쟁점의 행위시점(계약 체결일·불법행위일·해고일 등)을
사건컨텍스트.사실관계에서 특정한다. 불명확하면 `[변호사 확인 필요]`.

**조회 시점** (둘 중 하나에 해당하면 수행):
- (a) 현행 파일 frontmatter `시행일자`가 오늘 이후 — 수록본이 아직 시행 전
- (b) 최종 커밋일이 기준일 이후 — 행위 후 개정 가능성

**절차**:
1. `git -C legalize-kr log --format="%h %ad" --date=short -- "kr/{법령}/{파일}.md"`
   로 버전 이력을 나열한다.
2. 최신 커밋부터 `git -C legalize-kr show {해시}:"kr/{법령}/{파일}.md"` 로
   frontmatter `시행일자`를 확인해 **시행일자 ≤ 기준일인 가장 최신 버전**을 채택.
   - **역전 점검**: 채택 후보에서 멈추기 전에 1~2커밋 더 내려가, 더 옛 커밋의
     시행일자가 채택 후보보다 늦으면서 기준일 이전인 경우(공포 순서와 시행
     순서의 역전 — 실재함)가 있는지 확인한다. 역전이 있으면 양 버전의 대상
     조문을 대조해, 동일하면 그대로 진행하고 다르면 두 버전 모두 발췌 후
     `[변호사 확인 필요 — 적용 법령 버전]` (스냅숏은 공포 반영본이라 기준일
     시점의 정확한 통합본이 저장소에 없을 수 있다).
3. 채택 버전과 현행(HEAD)의 해당 조문을 대조한다(줄바꿈 차이는 무시).
   - **동일** → 현행 핀으로 인용하고 발췌 아래 한 줄 부기:
     `[행위시 확인: 기준일 YYYY-MM-DD 시행 버전({해시})과 조문 동일]`
   - **차이** → 행위시 버전 조문을 발췌하고 아래 연혁 핀으로 인용. 현행 조문도
     함께 발췌해 차이를 표시하고, 부칙의 적용례·경과조치를 확인해 발췌한다.
     부칙 확인 범위: 차이를 만든 개정의 부칙은 **현행(HEAD) 파일**에 있다 —
     HEAD의 해당 공포번호 부칙과 채택 버전 파일 내 부칙을 모두 본다.
     적용 버전의 최종 판단은 `[변호사 확인 필요 — 적용 법령 버전]`.

**연혁 핀 표기**:

`[출처: kr/{법령}/{파일}.md@{해시} | 시행 YYYY-MM-DD | 기준일 YYYY-MM-DD]`

- 검증 재현: `git -C legalize-kr show {해시}:"kr/{법령}/{파일}.md"` 로 누구든
  같은 버전을 열 수 있다(기계 검증 가능성 유지).
